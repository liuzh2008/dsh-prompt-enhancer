# DSH 升级后 100.66.1.3:3081 无历史对话 + crypto.randomUUID 报错 — 问题修复记录

- **日期**：2026-08-25
- **影响范围**：DeepSeek Harness Web GUI（dev 实例，端口 3081）
- **状态**：✅ 已修复（用户确认）

---

## 一、背景

将 `deepseek-harness-dev` checkout（plugin-dev 分支，rc.5）升级到官方
`dsh-v0.1.1-rc.2`（origin/master，跨 855 提交）。升级完成后重启 3081 实例。

## 二、问题现象

1. 访问 `http://100.66.1.3:3081/`（本机 LAN IP）时，**没有既往的对话和工作区**；
   而 `http://127.0.0.1:3081/` 正常显示历史。
2. 在 100.66.1.3 页面选择工作区时，浏览器控制台报错：
   **`crypto.randomUUID is not a function`**。

## 三、根因分析

### 3.1 服务端排除（确认无问题）

对两个地址做了全面对比验证，服务端无任何差异：

| 验证项 | 127.0.0.1:3081 | 100.66.1.3:3081 |
|---|---|---|
| index.html 内容 | 字节一致 | 字节一致 |
| client bundle rev 列表 | 完全一致 | 完全一致 |
| WebSocket `/api/events.mux` | 连通 | 连通 |
| `workspace.list`（HTTP RPC） | 200 + 完整数据 | 200 + 完整数据 |

`workspace.list` 返回两个工作区完整数据（DSH-Workspace 10 会话、MedAiAssistant
43 会话），trust fence 对 100.66.1.3 正确放行（`--trusted-host` 生效）。

### 3.2 真正根因：浏览器端 `crypto.randomUUID` 仅限 secure context

- `crypto.randomUUID` 是 Web API，**只在 secure origin（HTTPS / localhost）暴露**；
- 通过 `http://<LAN-IP>:3081`（如 100.66.1.3）访问时是 **plain-HTTP 非 secure
  context**，`crypto.randomUUID` **不存在**；
- `127.0.0.1` 属于 localhost（secure context），所以 127.0.0.1 正常、
  100.66.1.3 报错——与现象完全吻合。

调用点（升级后仍直接使用 `crypto.randomUUID()`）：

- `packages/host/apiproxy/src/fetch/client.ts` → `AbstractApiClient.mintRpcId()`
  （每个 RPC 请求都要生成 correlation id，工作区/会话列表初始化必触发）
- `packages/client/ui-conversation/src/client/service.ts` → 草稿附件 id
- `packages/llm/llm/src/message.ts` → 消息 id

### 3.3 为何升级时漏掉此修复

本地 plugin-dev 分支上有提交
`07e61e768f fix(client): avoid secure-context-only crypto.randomUUID on plain-HTTP
LAN origins`（2026-08-14，正是修这个问题的）。

升级时判断"官方 rc.1.2 已解决"而跳过，依据是官方 master 的
`packages/client/connection/src/websocket-downlink.ts` 用了 `node:crypto` 的
`randomUUID`。但那只覆盖了 **host 侧（Node 环境）**；**浏览器侧 client 代码
官方从未修复**（官方 master 的 `mintRpcId()` 仍直接调 `crypto.randomUUID`）。
属误判，导致浏览器端问题在升级后暴露。

## 四、修复方案

将本地提交 `07e61e768f` cherry-pick 到升级分支 `upgrade-rc12`：

```bash
git cherry-pick 07e61e768f   # 干净合入，无冲突（6 文件，+104/-21）
```

修复内容：

1. **新增 `packages/host/apiproxy/src/fetch/uuid.ts`**：`randomUuid()` 工具——
   优先用原生 `crypto.randomUUID`（存在时），否则回退到
   `crypto.getRandomValues`（所有 origin 均可用），生成 RFC 4122 v4 UUID。
2. **`packages/host/apiproxy/src/fetch/client.ts`**：`mintRpcId()` 改用 `randomUuid()`。
3. **`packages/llm/llm/src/uuid.ts`**（新增）+ `message.ts`：消息 id 同法修复。
4. **`packages/client/ui-conversation/src/client/service.ts`**：草稿附件 id 改用
   本地 `randomUuid()`（getRandomValues 回退）。
5. **`packages/host/apiproxy/tests/fetch-carrier.spec.ts`**：新增
   insecure-origin minting 回归测试。
